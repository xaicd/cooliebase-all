# CoolieBase-All-Next 企业级数字员工 (Agent) 治理中枢与 KPI 量化考核规范
# (Enterprise Agent Governance & Quantifiable KPI Framework for Heavy Business)

> **设计来源**: 深度吸收 Coolie 工坊控制面与 Palantir FDE 作战体系实战沉淀  
> **模板使命**: 为基于 `cooliebase-all-base` 孵化的重型业务系统（ERP、MES、SCM、金融结算）提供原生的 AI 数字员工编制、调度、预算硬停与量化履约考核中枢。

---

## 一、 为什么重型企业级业务必须学习 Coolie 工坊的 Agent 管理机制？

传统业务系统往往将大模型（LLM）仅仅作为离散的“聊天助手”外挂。一旦进入真实的重型业务（如自动审核采购单、自动核销对账、异常排查）：
1. **失控风险**：没有预算熔断，一个死循环几千元 Token 瞬间蒸发；
2. **踩踏风险**：没有单写者排他锁，多个 Agent 并发篡改同一份单据状态；
3. **推诿风险**：职责划分不清，出了生产故障无法归因责任员工；
4. **无法量化**：缺乏数据化 KPI，不知道数字员工到底替企业省了多少人效。

Coolie 工坊跑通了完整的“6 大员工 × 7 工具池”实战闭环，其核心管理机制必须成为 `cooliebase-all-base` 的标准基础设施。

## 二、 Coolie 工坊 Agent 治理六大核心机制在重型业务底座中的落地

### 1. 复合逻辑实体模型 (Agent as Complex Logical Object)
每个业务数字员工不是一段 Prompt，而是数据库中具有独立主键的复合对象：
- **身份标识**: `id`, `name`, `roleLabel`
- **中文 2 字技能**: `skills: ["对账", "审核", "巡检", "预警"]`
- **底层工具绑定**: `tools: ["sql-executor", "erp-connector", "wechat-notify"]`
- **上下级汇报树**: `reportsTo: <supervisor-agent-id>`

### 2. 严格的月度预算硬停与自动熔断 (Budget Hard-Stop & Circuit Breaker)
- 在企业级业务中，给每一个 Agent 配置 `budget_monthly_cents`；
- 每次 Agent 消耗 Token 或调用付费接口，实时扣减并累加 `spent_monthly_cents`；
- 一旦超支，系统级自动置为 `paused`，挂载 `pause_reason: "budget_exceeded"`，必须由管理员审批提额后方可恢复，彻底杜绝资费事故。

### 3. 单写者并发纪律与排他锁 (Single-Writer Rule)
- 任何关键业务对象（如合同单据、结算批次），同一时间**只允许一个 Agent 或一个操作人持有写锁**；
- 任务执行期间必须挂载操作锁（Operation Lock），未释放前其他 Agent 自动进入等待队列。

### 4. 派单收据 (Dispatch Receipt) 与执行证据账本
- 触发业务 Agent 执行时，系统必须生成不可变的 `Execution Receipt`，记入审计流水；
- Agent 执行完毕必须回写：
  - 变更前后 Data Snapshot Diff；
  - 规则执行结果与决策依据；
  - 耗时、消耗 Token 与操作人。

### 5. 心跳监控与状态机收敛 (Heartbeat & State Machine)
- Agent 状态机收敛为标准四态：`idle (空闲) -> running (运行) -> paused (暂停) -> error (异常)`；
- 运行中必须定期上报心跳 (`last_heartbeat_at`)，超过 5 分钟无心跳自动标记为 `stalled` 并触发钉钉/企业微信预警。
